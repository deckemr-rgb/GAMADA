# Celah lintas produk (dari critic)

- **[cross-cutting] Every spec needs Postgres/Redis/Midtrans/MinIO, but the portfolio at gatraglobal.id (and the Vite SPA at 127.0.0.1:5173) is static. Nothing says how the /karya and /tools demos stay fully usable in the browser with no backend.** → Each product ships two data adapters behind one interface. `live` uses the Hono/FastAPI API. `demo` runs in the browser (IndexedDB + MSW handlers + seeded data) and has a 'Simulasikan pembayaran QRIS' button that fires the same state transition as the webhook. Acceptance: Playwright runs each product's main journey against `vite preview` with the network blocked except for static assets, with 0 failed requests and the journey reaching its final state.
- **[cross-cutting] Only KasirKu defines a public demo tenant that resets. The other demos (GoKantin, Tiket.in, LENSA, SmartCast, Kopi Senja, mobile web exports) have no reset rule, so state left by one visitor carries over to the next.** → Demo state is scoped per browser (IndexedDB namespace) and has a 'Reset demo' button. Server-side demo tenants reset at 03:00 WIB via a BullMQ cron. Test: mutate data, click reset, and a DB/IndexedDB snapshot equals the seed hash.
